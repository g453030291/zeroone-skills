# 当日情报的 schema 与写作标准

产出是 `~/.zeroone/industry-insight/summaries/<profile>/YYYY-MM-DD.json`，一天一个文件。结构化而非 markdown，好处是 dashboard 不用解析、其他工具能直接消费、字段缺失能被校验住。

## 读者是谁

**普通用户，不是行业分析师。** 他们关注这个领域，但不一定懂黑话，也没时间读四篇原文。他们想知道：发生了什么、几家说法有没有出入、这事跟我有没有关系。

由此三条：

- **说人话。**「渠道库存优化」→「压在经销商手里的车太多，得清一清」。必须用专业词时顺手解释一句。
- **事实和观点分开。** 读者要能一眼看出哪句是报道写的、哪句是你推的。混在一起的分析没价值，因为读者无法判断该信多少。
- **每个事实能追溯。** 带 url，不带来源的断言等于没有。

## Schema

你只写 `highlights` / `topics` / `skipped` 三块，其余由 `digest.py --record` 回填。

```json
{
  "highlights": [
    "行业权威给出的数据比体感更差：6 月乘用车销量同比降 26.4%",
    "轮胎行业 7 月一个月推进至少五个扩产项目，报道自己也在警告内卷",
    "极氪 9X 五座版上市 47.19–58.59 万元，同期奔驰中国销量降近 30%"
  ],
  "topics": [
    {
      "topic_key": "anqingheng-market-outlook",
      "cluster_id": 3,
      "title": "安庆衡：国内乘用车销量下滑超两成",
      "tldr": "中国汽车工业咨询委员会主任在研讨会上给出一组相当悲观的数据——国内已进入深度存量竞争，价格战的以价换量效果在递减，全行业还没找到扭转盈利下滑的办法。",
      "facts": [
        {"text": "6 月乘用车销量同比下降 26.4%，超过四分之一", "url": "https://mp.weixin.qq.com/s/xxx"},
        {"text": "不到半年全国已上市 544 款新车，中小品牌生存空间被压缩", "url": "https://mp.weixin.qq.com/s/xxx"}
      ],
      "cross_source": "两家都完整转载了同一篇发言整理稿，落点没有差异；数字口径也一致。",
      "source_note": "车百智库和车百会研究院是同一机构的关联账号，属同一篇稿的两次发布，不构成两个独立信源的相互印证。建议对照中汽协原始发布再确认。",
      "implications": [
        "如果 24.3% 的降幅属实，它和「出口大涨、新能源渗透率上升」是同时成立的——国内燃油车基本盘在快速塌缩，增量几乎全靠出口和新能源填补。",
        "对普通消费者最直接的影响：终端优惠大概率继续，但中小品牌售后风险在上升，买车时厂商存续能力比一年前更值得考虑。"
      ]
    }
  ],
  "skipped": [
    {"topic_key": "shangqi-reshuffle", "title": "上汽人事调整", "reason": "2026-07-28 已写过且无新增文章"}
  ]
}
```

### 字段说明

| 字段 | 必填 | 说明 |
|---|---|---|
| `highlights` | 有话题时必填 | 「今天值得看的 N 件事」，整篇的入口，读者可能只看这段。每条自带最关键那个数字，别写「关注 X 领域动态」这种空话。 |
| `topics[].topic_key` | ✅ | 小写英文短横线 slug，**跨天稳定**，同一件事复用同一个 key |
| `topics[].cluster_id` | ✅ | 脚本据此回填 `sources` 和 `article_ids`，缺了会被校验拦下 |
| `topics[].title` | ✅ | 中文标题，平实陈述，不要「重磅！」「突发！」 |
| `topics[].tldr` | ✅ | 两三句说清这件事和它的意义 |
| `topics[].facts[]` | 建议 | `{text, url}`。数字照抄原文，别四舍五入、别换算单位 |
| `topics[].cross_source` | 建议 | 交叉比对，见下 |
| `topics[].source_note` | 有伪交叉时必填 | 见下 |
| `topics[].implications[]` | 建议 | 分析判断。dashboard 会自动标注「非事实」，你不用再写免责声明 |
| `skipped[]` | 建议 | 让读者知道你看过了、判断为无新进展，而不是漏了 |

`sources` / `article_ids` / `stats` / `generated_at` / `profile` / `date` **不要手写**，`--record` 会回填。

## cross_source 怎么写

这是整篇最有价值的部分——单个信源给不了它。别写成敷衍的「多家媒体均有报道」。可写的角度：

- **落点差异**：同一件事，有人当利好写，有人当危机写
- **独家信息**：只有一家提到的细节，标明只有它提到
- **立场差异**：行业媒体的通稿口径 vs 财经媒体的质疑
- **数据出入**：同一指标的不同版本，说明可能的口径差异
- **谁在转述谁**：多家都在转同一份通稿时要点破，那不算多信源印证

## source_note：两种伪交叉

看起来是多信源、实际只有一个：

1. **同一个公众号一天发两篇**讲同一件事
2. **关联账号互相转发**同一份通稿（如同机构的「X 智库」和「X 研究院」）

碰到就明确写出来，例如：「这两篇都来自『轮胎商业』一个公众号，属于同一信源的两次报道，不是交叉印证。」读者据此判断该信多少，这比多凑一个信源数有价值得多。

## implications 的分寸

每条推论都要能追到 `facts` 里列出的事实。不知道就说不知道——**「目前还看不出来」是一个合格的结论，编一个不是。**

可以有一条讲「对普通读者的实际含义」（这事跟你的实际决策有什么关系），但**跟读者无关就别硬凑**。

## 增量更新（action 为 update 的话题）

不重讲全部背景，写清两件事：新进展是什么、原来的判断有没有变。推翻了就直说。`tldr` 里点明这是对某天判断的更新。

## 今天没有内容时

```json
{"highlights": ["今天没有值得展开的跨源话题：命中 12 篇但都是孤立单篇"], "topics": [], "skipped": [...]}
```

这是合格产出，不是失败。**绝对不要为了交作业把单篇消息硬凑成话题。**

## 常见毛病

| 别这样 | 这样 |
|---|---|
| 「业内人士普遍认为…」 | 谁说的？哪家媒体？带 url |
| 「这将深刻改变行业格局」 | 具体改变什么？谁受益谁受损？ |
| 把四篇内容顺序拼在一起 | 按事实 / 分歧 / 判断重组 |
| 观点混进 facts | 放进 implications |
| 同号两篇当成两个信源 | 写进 source_note |
| 为凑字数硬写「实际含义」 | 跟读者无关就删掉 |
| 没内容硬凑一期 | topics 给空数组，说明原因 |
