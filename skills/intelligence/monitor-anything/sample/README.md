# sample/articles.json

**本批数据由 AI 合成，用于演示 monitor-anything 的采集、清洗、筛选、聚类、摘要与渲染流程，
不是真实抓取内容。** 涉及的公司、人物言论、产品参数、事件细节均为虚构，请勿作为真实资讯引用
或传播。

## 为什么用合成数据而不是脱敏真实数据

Sample 的作用不是证明"我们有你要的数据"——那不可能覆盖每个人的长尾关注方向。它只证明
"你即将看到的东西长这样"：结构与真实报告完全一致，跑一遍就知道 setup 之后每天会收到什么。
真正建立信任的是 setup 流程最后生成的、基于你自己关注方向的第一份真实报告。

## 数据里刻意埋了什么

- **3 组跨源聚类素材**（主题「AI 与智能汽车」）：
  1. 小米汽车「澎程」系列发布会——4 篇公众号不同角度 + 2 篇小红书体验向 + 1 篇纽约时报产业分析
  2. 地平线征程7芯片发布——3 篇公众号 + 1 篇小红书 + 1 篇 AI 热点
  3. 英伟达下调 H20 报价——2 篇公众号 + 1 篇小红书
- **明显的重复转载**：两组文章分别被 2~3 个不同公众号转发同一篇内容（同一 URL，部分带
  `chksm` / `scene` / `from` 等追踪参数），用于验证 URL 去重逻辑真的在生效
- **一批噪音**：广告、招聘、限时优惠、标题党、引流进群，用于验证清洗阶段确实在过滤
- **若干小红书条目 `clean_content` 为空**：用于验证空正文的兜底处理（仅标题判定）
- 其余 ~200 条为模拟的日常信息流长尾内容，围绕智能汽车与 AI 话题，来源分布、发布时间、
  正文长度均有意做了随机化，让整体数据形态接近真实的一天

## demo-dashboard.html

这是拿 `articles.json` 跑完整套六阶段流水线后实际生成的 dashboard，可以直接双击打开看效果
（跨源聚类、AI 判断依据折叠区、筛选实例、来源分布、线索区都是真实跑出来的，不是手绘的截图）。
正式使用时这个文件会被 `data/reports/dashboard.html` 取代，这份放在 `sample/` 下只是方便
你在安装前先睹为快。

## 用途

`scripts/harvest.py run --sample` 会读取这份数据代替真实接口调用，走一遍完整的采集清洗
流程；后续的筛选、聚类、摘要阶段由 Agent 按 `prompts/` 中的说明处理这批数据，最终产出的
`dashboard.html` 顶部会明确标注"这是一份示例报告"。
