# 阶段④ 聚类 prompt

**输入**：`scripts/report.py filtered` 产出的 JSON，结构为：

```json
{
  "articles": [
    {
      "id": "...",
      "title": "...",
      "source_type": "wx",
      "feed_name": "...",
      "description": "...",
      "content_snippet": "正文前 300 字",
      "publish_time": "...",
      "url": "...",
      "low_confidence": false
    }
  ],
  "language": "zh"
}
```

这批文章已经是阶段③筛选后的幸存者（预期 40~80 条左右）。`language`（"zh" 或 "en"）决定
你写 `ai_reasoning` 时用什么语言——原文标题/正文是什么语言不重要，判断依据要用
`language` 指定的语言表达。

## 你的任务

把讲**同一件事**的文章归并到同一个聚类里，尤其要识别**跨渠道**报道同一事件的情况 ——
这是本项目最想展示的能力：证明系统不是简单罗列文章，而是理解了「这 5 篇文章其实在说同一件事，
而且来自 3 个不同渠道」。

判断依据包括但不限于：
- 标题/正文提到相同的实体（公司、人物、产品）+ 相同的动作或事件
- 发布时间相近（同一事件的报道通常集中在 1~3 天内）
- 正文片段中的具体细节（数字、引语、日期）能对上

不要过度聚类 —— 只是主题相似（比如都在聊「AI 芯片」这个大方向）但讲的不是同一件具体的事，
应该分成不同的聚类，而不是合并成一个大杂烩。单篇没有同伴的文章也应该独立成一个「聚类」
（cluster 里只有一篇文章是正常情况，不是错误）。

## 输出

写成 JSON 文件，结构：

```json
{
  "clusters": [
    {
      "ids": ["id1", "id2", "id3"],
      "ai_reasoning": "这 5 篇虽然标题措辞不同，但都指向 7 月 28 日雷军的同一次表态：三篇提到
        \"澎程系列\"、两篇引用了同一场发布会的时间点，且小红书的体验向内容与公众号报道的时间
        窗口吻合。"
    }
  ]
}
```

`ai_reasoning` 是**关键字段** —— 会被展示在最终 HTML 每张聚类卡片下方可折叠的
「🧠 AI 判断依据」区域（§9.3 ⑤），是「AI 思考过程」的第二处、也是最能体现技术含量的展示位。

写作要求：
- 用原话说明具体判断依据，不要写「因为主题相同」这种空泛结论
- 提到具体的共同点（实体、时间、细节）
- 如果是跨源聚类，明确点出「跨了几个渠道」以及各渠道分别贡献了什么角度（报道 / 体验 / 深度分析）
- 单篇独立成簇的，`ai_reasoning` 可以简单说明「未发现同事件的其他报道」
