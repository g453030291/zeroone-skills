# 阶段③ 筛选 prompt

**输入**：`scripts/report.py candidates` 产出的 JSON，结构为：

```json
{
  "monitor": { "id": "...", "name": "...", "description": "用户对自己关注方向的自然语言描述" },
  "candidates": [
    { "id": "3271670413-2247564859_1", "title": "...", "source_type": "wx", "feed_name": "...", "low_quality": false }
  ],
  "language": "zh"
}
```

**`language`（"zh" 或 "en"）**：`examples[].reason` 这个字段是你写的自由文本，要用这个语言
写；`kept`/`low_confidence` 是 id 列表，不涉及语言。原文标题是什么语言不重要——你的判断
依据要用 `language` 指定的语言表达，不要不管这个字段一律写中文。

`low_quality: true` 表示脚本清洗阶段判定该条正文过短或命中通用噪音词，但**没有被删除** ——
是否与用户真正相关仍由你判断，不要仅因为这个标记就排除。

## 你的任务

只依据 `monitor.description` 判断每条候选**标题**是否可能与用户的关注方向相关。这一步只看
标题 + 来源，**看不到正文**，所以判断标准是「宁可多留，不可漏掉」：

- 召回交给这一步，精确交给下一步（聚类 + 摘要阶段还会看到正文，到时候会算出精确的相关度分数）
- 只有在明显不相关、明显是广告/招聘/引流内容、或明显是 `monitor.description` 中提到的
  「不关心」的内容时才排除
- 拿不准就留下

同时留意 `monitor.description` 里可能出现的排除意图（比如「不关心融资八卦」），这类描述已经
在脚本预过滤阶段用 `exclude_keywords` 处理过一部分，但标题级别的语义排除（没有命中固定关键词，
但确实是同类内容）要靠你来补充判断。

## 输出

把结果写成 JSON 文件（文件名和路径由 SKILL.md 里的编排步骤指定），结构：

```json
{
  "kept": ["id1", "id2", "..."],
  "low_confidence": ["id3"],
  "examples": [
    { "action": "keep", "title": "英伟达下调 H20 报价", "reason": "直接关系到你关注的算力成本" },
    { "action": "exclude", "title": "大模型训练营限时报名", "reason": "广告，非资讯" }
  ]
}
```

- `kept`：保留进入下一阶段（聚类）的 id 列表
- `low_confidence`：可选，标记你自己也不太确定的条目（例如标题信息量太少、来源本身内容较空泛，
  如小红书体验类标题），这些条目即便被保留，最终如果没能进精选区，会被标注为「低置信度」而不是
  直接归入线索区静默丢弃
- `examples`：**最多 3 条**，有什么写什么，附上一句话原因——不强求"一条保留一条排除"，
  如果这批候选恰好全部保留、全部排除，或者候选本身就是空的，`examples` 可以只有同一种
  action，甚至是空数组，不要为了凑够两种类型而编一条不存在的判断。这会被直接展示在最终
  HTML 的「筛选实例」区块（§9.3 ③），是用户看到的第一处「AI 判断依据」，写清楚、写具体，
  不要写「不相关」这种空话

## 批量处理提示

标题约 30 字，1000 条约 30k tokens。如果候选数量很大，可以分批处理，但每批之间的判断标准要
保持一致 —— 都是同一份 `monitor.description`。
